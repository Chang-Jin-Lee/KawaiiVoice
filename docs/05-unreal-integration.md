# 언리얼 엔진 통합 (탑다운 슈터)

변환된 WAV를 게임에 넣는 단계. 변환 품질과 별개로 **여기서 망가지는 경우가 많다.**

## 납품 규격

| 항목 | 값 | 이유 |
|---|---|---|
| 포맷 | WAV PCM, 모노 | 언리얼이 임포트 시 처리. 대사는 모노가 표준 |
| 샘플레이트 | 48kHz | 프로젝트 마스터와 일치시켜 리샘플링 단계 축소 |
| 비트뎁스 | 24bit (또는 16bit) | 임포트 후 어차피 압축된다 |
| 라우드니스 | 프로젝트 기준으로 일괄 정규화 | **파일별 편차가 게임에서 가장 티 난다** |
| 앞뒤 무음 | 트림 | 전투 바크의 반응 지연 방지 |
| 파일명 | 규칙 고정 | 아래 참조 |

```
VO_<캐릭터>_<카테고리>_<번호>.wav

VO_Sakura_Bark_Reload_01.wav
VO_Sakura_Bark_EnemyBehind_03.wav
VO_Sakura_Hit_Light_02.wav
VO_Sakura_Death_01.wav
VO_Sakura_Skill_Ultimate_01.wav
VO_Sakura_Cutscene_Ch01_015.wav
```

**변환 전 원본과 변환 후 산출물의 파일명을 반드시 일치시킨다.** Applio `batch_infer`는 입력 폴더 구조를 기준으로 출력하므로, 원본 명명 규칙을 처음부터 언리얼 규칙에 맞춰 두면 재작업이 없다.

## 임포트 및 압축

- **Sound Wave** 에셋으로 임포트.
- **Compression Quality** — 대사는 명료도가 중요하므로 SFX보다 높게. 전투 바크는 물량이 많아 용량과 트레이드오프가 생긴다. 카테고리별로 다르게 잡을 것.
- **플랫폼별 압축 포맷**과 샘플레이트 품질 설정은 Project Settings의 오디오 플랫폼 설정에서 관리. 목표 플랫폼 기준으로 실측할 것.
- **긴 컷신 대사는 스트리밍**, 짧은 바크는 메모리 상주가 유리하다.

## 탑다운 슈터에서 실제로 중요한 것

### 1. Sound Concurrency — 대사 겹침 제어

탑다운 슈터는 적이 몰리고 이벤트가 동시에 터진다. 제어하지 않으면 **캐릭터가 자기 대사를 여러 개 동시에 말한다.** 즉시 몰입이 깨지는 대표적 버그다.

- **Sound Concurrency** 에셋을 만들어 카테고리별 최대 동시 재생 수를 제한한다.
- 캐릭터 대사는 보통 **동시 1개**가 맞다.
- 해결 규칙(Resolution Rule)을 정한다 — 새 대사가 기존 것을 끊을지, 아니면 새 대사를 버릴지. **피격·사망은 끊고 들어가야 하고, 일반 바크는 버려야 한다.**

### 2. 바크 쿨다운과 우선순위

- 같은 대사가 연속 반복되면 즉시 싸구려로 들린다. **최근 재생 이력을 저장해 같은 변형을 연속 선택하지 않도록** 한다.
- 카테고리별 쿨다운을 둔다 (예: "재장전" 대사는 N초 내 재발화 금지).
- 우선순위: `사망 > 피격 > 궁극기 > 적 발견 > 일반 바크`

### 3. MetaSounds로 변형 랜덤화

MetaSound 안에서 Wave Player + 랜덤 선택 노드로 같은 상황의 여러 테이크를 무작위 재생한다. 미세한 피치·볼륨 랜덤화를 함께 걸면 반복감이 줄어든다.

**주의: 피치 랜덤화 폭을 크게 주지 말 것.** 이미 RVC로 피치를 이동시킨 소스이므로 추가 시프트가 크면 음색이 무너져 "다른 사람"처럼 들린다. ±2~3% 정도로 제한한다.

### 4. 대사 더킹 (Ducking)

전투 중 BGM·총성에 대사가 묻힌다. **Sound Class** 계층을 만들고, 대사 클래스가 재생될 때 음악·SFX를 일시적으로 낮추는 **Passive Sound Mix Modifier**를 설정한다.

탑다운 슈터는 화면상 캐릭터가 작아 입 모양 단서가 없다. 대사를 놓치면 정보 전달이 실패하므로 더킹은 선택이 아니라 필수다.

### 5. 공간화 — 대사는 대체로 2D

- **플레이어 캐릭터 대사**: 2D 재생. 탑다운 시점에서 플레이어 캐릭터는 화면 중앙 부근이고, 감쇠를 걸면 오히려 부자연스럽다.
- **적·NPC 대사**: 3D + Attenuation. 위치 정보가 게임플레이 단서가 된다.
- 탑다운은 카메라와 캐릭터의 거리가 일정하므로, 3인칭·1인칭 프로젝트의 감쇠 커브를 그대로 가져오면 안 된다. **탑다운 전용으로 다시 잡을 것.**

### 6. 현지화 구조

한국어 외 언어를 계획한다면 처음부터 **Dialogue Wave / Dialogue Voice** 구조를 잡아 두는 편이 낫다. 나중에 수백 개 Sound Wave를 재구성하는 비용이 크다.

한국어만 출시할 계획이라도, 캐릭터·상황 메타데이터를 에셋에 붙여 두면 대사 관리가 편해진다.

## Wwise / FMOD 를 쓸 경우

미들웨어를 쓰면 위 항목(동시성, 랜덤 컨테이너, 더킹, 쿨다운)이 대체로 더 편하다.
- **Random Container** — 변형 재생 + 반복 회피 내장
- **Voice Limiting / Playback Limit** — 동시 재생 제어
- **Ducking** — 버스 단위로 선언적 설정
- 사운드 디자이너가 언리얼 빌드 없이 작업 가능

**단 라이선스 비용이 발생한다.** 인디 규모라면 언리얼 내장(MetaSounds + Sound Concurrency + Sound Mix)으로 충분하다.

## 검수 체크리스트

- [ ] 파일별 라우드니스 편차 없음
- [ ] 캐릭터 대사 동시 재생 1개로 제한
- [ ] 같은 대사 연속 반복 방지 로직 있음
- [ ] BGM·총성 위에서 대사 명료도 확보 (더킹)
- [ ] 앞 무음 트림 — 반응 대사가 늦게 들리지 않음
- [ ] 전투 최대 부하 상황에서 대사가 밀리거나 씹히지 않음
- [ ] **캐릭터 대사 전체를 연속 재생했을 때 음색이 일관됨** ← 변환 품질 최종 검수
- [ ] 목표 플랫폼에서 압축 후 품질 실측 (치찰음 아티팩트 확인)
